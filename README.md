# Техническое задание

## 1. Название проекта

**log-analyzer** — CLI-утилита для анализа текстовых лог-файлов.

---

## 2. Цель проекта

Создать высокопроизводительную консольную программу на Rust для обработки больших лог-файлов с возможностью фильтрации, агрегации и вывода результатов в различных форматах.

Проект предназначен для:

* освоения базовых и промежуточных концепций Rust;
* практики работы с потоками данных и ошибками;
* понимания подхода Rust к производительности и безопасности памяти.

---

## 3. Область применения

* Анализ application / server логов
* Быстрая офлайн-обработка больших файлов (100 МБ – несколько ГБ)
* Использование в CI, диагностике, ручном анализе

---

## 4. Формат входных данных

### 4.1 Общий формат строки лога

Каждая строка — одно событие.

Формат (строго фиксированный):

```
<timestamp> <level> <service> <message>
```

### 4.2 Описание полей

| Поле      | Тип    | Пример               | Описание |
| --------- | ------ | -------------------- | -------- |
| timestamp | string | 2025-12-01T10:15:30Z | ISO-8601 |
| level     | enum   | INFO / WARN / ERROR  | Уровень  |
| service   | string | auth-service         | Источник |
| message   | string | User logged in       | Текст    |

---

## 5. Функциональные требования

### 5.1 Обработка файла

* Принимает путь к лог-файлу
* Читает файл построчно (streaming, без загрузки целиком)
* Корректно обрабатывает файлы размером >1 ГБ

### 5.2 Фильтрация

Поддерживаемые фильтры (могут комбинироваться):

* по уровню логов (`--level`)
* по сервису (`--service`)
* по подстроке в сообщении (`--contains`)
* по временному диапазону (`--from`, `--to`)

### 5.3 Агрегации

* Общее количество строк
* Количество строк по уровням логов
* Топ-N самых частых сообщений
* Топ-N сервисов по количеству логов

### 5.4 Режимы вывода

* Человекочитаемый текст (stdout)
* JSON

---

## 6. CLI-интерфейс

### 6.1 Пример вызова

```
log-analyzer ./app.log \
  --level ERROR \
  --from 2025-12-01T00:00:00Z \
  --to 2025-12-02T00:00:00Z \
  --top 5 \
  --format json
```

### 6.2 Поддерживаемые аргументы

| Аргумент   | Обязательный | Описание          |
| ---------- | ------------ | ----------------- |
| file       | да           | Путь к лог-файлу  |
| --level    | нет          | Фильтр по уровню  |
| --service  | нет          | Фильтр по сервису |
| --contains | нет          | Поиск в сообщении |
| --from     | нет          | Начало диапазона  |
| --to       | нет          | Конец диапазона   |
| --top      | нет          | Размер Top-N      |
| --format   | нет          | text / json       |

---

## 7. Нефункциональные требования

### 7.1 Производительность

* O(n) по количеству строк
* Минимальное количество аллокаций
* Без regex по умолчанию

### 7.2 Надёжность

* Корректная обработка битых строк
* Чёткая типизация ошибок
* Отсутствие panic в runtime

### 7.3 Качество кода

* Модульная структура
* Юнит-тесты для парсинга и фильтрации
* Clippy + rustfmt

---

## 8. Ограничения

* Только стандартный ввод/вывод
* Без базы данных
* Без UI
